# Contribution Art

> Искусство, нарисованное коммитами.

Этот репозиторий — небольшой эксперимент на стыке **Git, GitHub, программирования и визуального искусства**.

Идея простая: превратить стандартный зелёный график активности GitHub в холст и написать на нём текст. Для этого скрипт создаёт пустые Git-коммиты с датами в прошлом. GitHub учитывает такие коммиты в contribution graph, поэтому последовательность отдельных зелёных квадратов складывается в буквы, слова и целые фразы.

То есть здесь коммит — уже не только единица разработки. Он становится **пикселем**.

---

## Что здесь происходит

Главный файл проекта:

```text
generate.ps1
```

Это PowerShell-скрипт, который:

- принимает набор записей вида «год + текст»;
- превращает каждую букву в маленькую bitmap-маску;
- размещает текст по ширине одного годового графика GitHub;
- определяет конкретные даты, соответствующие «включённым» пикселям;
- создаёт на этих датах пустые Git-коммиты;
- использует дату автора и дату коммиттера в прошлом;
- отправляет получившуюся историю в GitHub.

После публикации GitHub строит contribution graph уже из этих коммитов.

В результате вместо обычного набора случайных зелёных клеток появляется что-то вроде:

```text
HELLO WORLD
```

или:

```text
STOP THE WAR
```

или любая другая короткая фраза, которую можно уместить в сетку.

---

## Зачем это сделано

Это не попытка искусственно показать «настоящую» историю программной активности.

Наоборот, смысл проекта в том, чтобы взять интерфейс GitHub, предназначенный для статистики, и превратить его в средство визуального выражения.

Contribution graph обычно отвечает на вопрос:

> «Насколько активно человек работал с GitHub?»

Здесь он начинает отвечать на другой вопрос:

> «Что можно написать, если считать каждый коммит пикселем?»

Получается своего рода программируемая типография внутри GitHub.

Обычный Git-коммит превращается в элемент изображения:

```text
commit → дата → клетка графика → пиксель
```

А последовательность таких пикселей превращается в:

```text
пиксели → буквы → слова → сообщение
```

Таким образом, GitHub contribution graph используется не только как статистический инструмент, но и как ограниченная графическая матрица.

---

## Почему именно GitHub contribution graph

У графика есть несколько интересных свойств:

- он состоит из дискретных клеток;
- каждая клетка соответствует определённому дню;
- количество коммитов влияет на интенсивность клетки;
- структура повторяется из года в год;
- результат виден непосредственно в профиле GitHub;
- для создания изображения не нужны SVG, Canvas или отдельная веб-страница.

Получается забавный парадокс: чтобы нарисовать букву, здесь не нужно рисовать. Нужно сделать историю Git.

---

## Как устроен рисунок

В скрипте используется собственный мини-шрифт. Каждая буква хранится как bitmap высотой в пять строк. Например, буква `E`:

```text
XXX
X..
XX.
X..
XXX
```

`X` означает включённый пиксель, а `.` — пустой.

Затем скрипт транспонирует эти строки в колонки, потому что contribution graph GitHub организован по неделям и дням. Каждый включённый пиксель превращается в конкретную дату.

### Почему пять коммитов на один пиксель

В настройках скрипта:

```powershell
$perDay = 5
```

Это означает, что один видимый пиксель создаётся пятью коммитами в один день.

Количество коммитов влияет на уровень зелёного цвета клетки GitHub:

```text
1 commit  → светлее
...
5 commits → более насыщенный пиксель
```

Поэтому коммиты здесь выполняют роль не только координаты, но и интенсивности цвета. Это превращает contribution graph в очень примитивный, но вполне рабочий растровый дисплей.

---

## Годы становятся отдельными холстами

Записи задаются в массиве:

```powershell
$entries = @(
  "1989 HELLO WORLD"
  "1990 IT WORKS!"
  "1991 OOPS!"
  ...
)
```

Первое число определяет год, а всё остальное — текст. Например:

```text
1994 JUST DO IT
```

означает: взять календарь 1994 года и использовать его contribution graph как холст для фразы `JUST DO IT`.

Текст автоматически центрируется по ширине доступной области. Таким образом, каждый год может стать отдельным кадром одной большой визуальной истории.

---

## Набор символов

Скрипт содержит bitmap-шрифт для:

- латинских букв A–Z;
- цифр 0–9;
- основных знаков пунктуации;
- части кириллицы;
- украинских букв, которых нет в русском алфавите.

Есть также таблица алиасов для кириллических букв, визуально совпадающих с латинскими:

```text
А → A    В → B    Е → E    К → K
М → M    Н → H    О → O    Р → P
С → C    Т → T    Х → X    І → I
```

Это позволяет использовать смешанный текст, не создавая отдельный bitmap для каждого похожего символа.

### Почему не используется настоящий текстовый рендеринг

Здесь сознательно нет полноценного шрифтового движка. Каждая буква задаётся вручную как маленькая матрица. Это даёт несколько преимуществ:

- результат полностью предсказуем;
- скрипт не зависит от установленных шрифтов;
- изображение одинаково строится на разных машинах;
- каждая буква является частью алгоритма;
- сам шрифт остаётся маленьким и понятным.

По сути, это самодельный 5-pixel font, адаптированный под структуру GitHub contribution graph.

## Работа с датами

Для каждого года скрипт определяет начало календарной сетки:

```powershell
$jan1  = [datetime]"$year-01-01"
$start = $jan1.AddDays(-[int]$jan1.DayOfWeek)
```

После этого координаты bitmap переводятся в даты.

- **Вертикальная координата** соответствует одному из пяти рабочих дней: понедельник – пятница.
- **Горизонтальная координата** соответствует неделе.

Дополнительно скрипт проверяет, чтобы дата не «утекала» в соседний год. Это важно, потому что календарная сетка GitHub начинается и заканчивается не обязательно ровно 1 января и 31 декабря.

### Защита от слишком длинных надписей

Один год имеет ограниченную ширину, поэтому перед генерацией проверяется количество колонок:

```powershell
if ($cols.Count -gt 53) {
    ...
}
```

Если фраза не помещается в годовой график, она пропускается. Это лучше, чем насильно впихивать текст и получать сломанный рисунок.

---

## dryRun

У скрипта есть режим пробного прогона:

```powershell
$dryRun = $true
```

В этом режиме коммиты не создаются. Скрипт только рассчитывает план и показывает количество необходимых коммитов. Это удобно для проверки изображения перед тем, как действительно изменить Git history.

После проверки:

```powershell
$dryRun = $false
```

и можно запускать настоящую генерацию.

---

## Почему коммиты пустые

Файлы проекта не меняются для каждого пикселя. Вместо этого используется:

```bash
git commit --allow-empty
```

То есть создаётся настоящий Git-коммит без изменения содержимого файлов. Это принципиальный момент эксперимента: содержимое коммита не важно. Важны:

- дата;
- количество коммитов;
- сообщение;
- положение этой даты на contribution graph.

Каждый пустой коммит фактически становится инструкцией: **«Зажги этот пиксель»**.

### Сообщения коммитов

Для коммитов используется сообщение вида:

```text
<год> <фраза>
```

Например:

```text
1994 JUST DO IT
```

Это делает саму Git-историю читаемой. Вместо бессмысленных `update`, `fix`, `test`, `change` в истории видно текст, который использовался для построения изображения.

---

## Почему используются даты в прошлом

Главная техническая идея эксперимента — переменные окружения Git:

```powershell
$env:GIT_AUTHOR_DATE
$env:GIT_COMMITTER_DATE
```

Скрипт задаёт обе даты вручную перед созданием коммита, например:

```text
1994-05-17 12:00:00
```

Git сохраняет эту дату в метаданных коммита, а GitHub использует её при построении contribution graph. Поэтому можно создать изображение для конкретного года, не создавая коммиты в тот исторический момент.

---

## Это настоящая история активности?

**Нет.** И это важно.

Репозиторий — арт-проект и технический эксперимент, а не достоверная реконструкция реальной активности разработчика. Коммиты с прошлыми датами созданы намеренно ради визуального эффекта.

Contribution graph здесь следует воспринимать как *генерируемое изображение, закодированное в Git history*. Это скорее программное граффити, чем журнал разработки.

---

## Почему проект интересен как эксперимент

Git обычно воспринимают как систему контроля версий. GitHub поверх него добавляет социальный слой: профили, репозитории, коммиты, contributions, графики активности.

Этот проект работает на совершенно другом уровне абстракции: он берёт метаданные Git и использует их как графическую систему координат.

```text
текст
  ↓
bitmap-шрифт
  ↓
координаты пикселей
  ↓
календарные даты
  ↓
Git-коммиты
  ↓
GitHub contribution graph
  ↓
изображение
```

Изображение здесь существует не как файл. Оно существует как структура истории Git.

Проект постепенно превратился из простого эксперимента с contribution graph в небольшой генератор:

Таким образом, `generate.ps1` — это маленький **компилятор текста в Git history**.

## Требования

- Windows;
- PowerShell (скрипт рассчитан в том числе на Windows PowerShell 5.1);
- Git;
- GitHub-репозиторий;
- доступ на push в этот репозиторий.

Для корректной работы с кириллицей файл `generate.ps1` рекомендуется сохранять в **UTF-8 with BOM**. Сам скрипт дополнительно настраивает кодировку консоли:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

---

## Запуск

Скрипт необходимо запускать изнутри Git-репозитория. Он проверяет это самостоятельно:

```bash
git rev-parse --is-inside-work-tree
```

Рекомендуемый порядок:

1. Включить `$dryRun = $true`.
2. Проверить количество создаваемых коммитов.
3. Выставить `$dryRun = $false` и выполнить настоящую генерацию.

Для публикации используется:

```bash
git push origin main
```

Название ветки меняется в настройке:

```powershell
$branch = 'main'
```

---

## Важное ограничение GitHub

GitHub не графический редактор, поэтому разрешение здесь очень маленькое: примерно **53 недели × 7 дней**, а генератор использует для букв только пять строк высоты.

Это не место для сложных иллюстраций, портретов или пейзажей. Зато короткие слова и фразы работают отлично. Именно ограничение делает эксперимент интересным: приходится думать как программист и рисовать как человек, у которого закончился холст.

## Итог

`contribution_art` превращает GitHub contribution graph в необычный графический носитель. Вместо того чтобы воспринимать зелёные квадраты как побочный продукт программирования, проект делает их самим результатом программирования.

Каждая клетка имеет дату. Каждая дата получает коммит. Каждый коммит становится пикселем. А тысячи маленьких Git-операций складываются в несколько слов, видимых прямо в профиле GitHub.

Это эксперимент о том, как далеко можно зайти, используя интерфейс не совсем по назначению. И немного о том, что даже Git history иногда хочется не только читать, но и рисовать.
